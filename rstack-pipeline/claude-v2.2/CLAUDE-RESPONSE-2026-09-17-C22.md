## Four reasoned cases — read through the contracts, not executed

1. **Completed audit, holds.** The dispatcher measures the plan's sha256 and sends path, revision and digest (orchestrator 17). The auditor measures the file it read; the values agree (auditor 20). It replies with the envelope — Result `holds`, Artifacts None, `Plan:` line with both digests — followed by the audit body whose Overall verdict is `holds`, with "Attempted and found nothing" (auditor 72–76). The orchestrator saves the complete reply to `logs/results/<N>.md`, references it in the run log, confirms Result equals the body verdict, archives any previous audit under its round name, and persists the completed reply as `plan-audit.md` with the Persisted-by line (handoff 43, 75; orchestrator 21, 29). The skill routes `1b holds` to state 2. The audit stays current only while its envelope digest equals the plan's digest now.
2. **Completed audit, refuted.** As above with Result `refuted` equal to the body's Overall verdict. Because it is a completed audit it is persisted as `plan-audit.md` — a refutation is an audit the planner must answer, not a failure to audit. The skill routes to 1r; the planner reads `plan-audit.md`, revises and responds; the revised plan goes to a new 1b with a newly measured digest.
3. **Digest unavailable.** The auditor cannot measure the plan it read. It replies with the envelope alone: Result `STOPPED`, Artifacts None, a blocker with its owner, and a `Plan:` line that keeps the dispatched digest and says `unavailable` for its own (auditor 20; handoff 62). There is no body and no Overall verdict, so nothing is fabricated and the equality rule has nothing to compare (handoff 75). The orchestrator accepts the token and the owned blocker as well formed (orchestrator 21), keeps the reply only in `logs/results/<N>.md` with its run-log reference, writes no `plan-audit.md`, archives nothing, gives no consumer an audit, leaves earlier audit files untouched, and follows the STOPPED route to the blocker's owner; a human-owned blocker stops the run. An earlier `holds`, even one whose digest still matches, does not let the run reach state 2 (orchestrator 29; handoff 75).
4. **Digests differ.** Dispatcher and auditor both measured, and the values disagree: the file changed between dispatch and read, or one measurement is wrong. Same reply shape as case 3, except that both measured digests appear in the `Plan:` line and neither is dropped or adjusted. Same persistence and routing. Resolution is a new 1b invocation with a fresh dispatch measurement once the blocker's owner has dealt with the cause; the stopped reply remains in the results log as history.

In all four the saved reply is AGENT_REPORTED. These readings show the three contracts agree; they do not show that an agent or an installed parser behaves this way.
