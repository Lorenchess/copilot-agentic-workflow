## Confirmed findings requiring correction

### R22-01 — P2: immutable manifests still name mutable inputs

Location: fable-v2.2/references/handoff-contracts.md lines 33–37 and 97–109; agents/rstack-tester.agent.md line 54.

The per-attempt manifest is immutable, but its Candidate field still names candidate.md and its input list includes current plan/matrix/report paths. On the next round those paths are overwritten; an archived candidate or matrix has a different path. The old immutable manifest cannot be updated, so opening its original path references yields new bytes or digest mismatches. Keeping the manifest itself is insufficient to preserve the evidence a previous review assessed.

Correction: before sealing the packet, snapshot every mutable input it relies on into an immutable, explicitly owned location and record those immutable paths. Current compatibility files may remain copies. Do not rewrite old packet references after the fact. No source checkout is needed to define this contract.

Static acceptance example: after attempt 2 and candidate 2 replace all current pointers, every path listed by attempt 1 still resolves to its original bytes and hash. This example was reasoned through; no execution was run.

### R22-03 — P2: the current-audit check does not bind the audited plan bytes

Location: fable-v2.2/pipeline/SKILL.md lines 124–129; references/handoff-contracts.md line 150; OPEN-DECISIONS.md OD-19.

This is a residual control gap acknowledged by Fable, rather than an observed runtime failure.

Correction: bind the audit to the plan content identity captured for that invocation and compare it with the current/candidate plan identity. Keep revision numbers for humans. Preserve the parser-owned artifact body if necessary by placing the identity in the new result/dispatch metadata; uncertainty about an existing parser need not leave this candidate's predicate revision-only. State the provenance limit and stop if the identity cannot be obtained.

## Risks and decisions, not confirmed runtime defects

- **OD-15, envelope persistence:** transport envelopes are useful, but the leading envelope must not become an assumed compatible parser migration. Saving the complete reply separately and extracting the artifact body byte-for-byte is a conservative port option. Actual parser behavior remains unknown; this review does not claim a parser was observed failing.
- **OD-14, recovery:** naming the restoration owner and reporting held user work improves the contract. Keeping it held until a human answers is an explicit policy proposal. Recovery must also preserve the stopped run's status; a restoration-only reply must not be mistaken for permission to resume its original blocker route.
- **OD-20, gate refresh:** define which gate evaluation release relies on and what happens when acceptance inputs change after a packet is sealed. Distinguish refreshing a gate evaluation from rerunning the suite. This is inherited unfinished design and matters before enabling exceptions.
- **Freeze protection:** checking whether the whole .rstack directory is ignored is narrower than checking whether the actual protected evidence paths are excluded from the actual stash operation. The real protection layout is unknown. Port against the actual file set; do not require ignoring governance just to protect evidence.
- **Comparison packet:** plain-file delivery addresses the reviewer's lack of Git. Exact reconstruction for binary changes, truncated diffs and unavailable source versions still needs explicit handling; keep INPUT_BLOCKED where the required content cannot be read.
- **Text cost:** Fable reports about 13% operational text growth. This review does not establish a behavioral or cost benefit. Avoid a broad rewrite while fixing these bounded issues.
