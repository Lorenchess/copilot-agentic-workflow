# 3. Unknown external-effect semantics

**FACT FROM FILE:** `pipeline/SKILL.md:168-178` records the attempt, marks UNKNOWN, requires a remote read, stops for unresolved effects and preserves the possibility of prior success. `handoff-contracts.md:232-251` requires append-only approval entries, intent before action and a new reconciliation line rather than rewriting UNKNOWN. The document already distinguishes history from later knowledge in prose. It is incorrect to report that reconciliation must leave the external state permanently UNKNOWN: line 251 explicitly permits a new reconciled outcome.

The remaining C1 problem is its representation and consumption:

1. `PUBLICATION_RESULT` is the only structured result field. It accepts either a returned result or reconciliation evidence, yet is immutable once entered. No named field or selection rule identifies which later line is the current justified conclusion (`handoff-contracts.md:236-251`). Different readers can reasonably retain the first UNKNOWN or treat an untyped later sentence as authoritative.
2. The new rule says to stop as `NEEDS_HUMAN` (`pipeline/SKILL.md:175`; approval agent:54), but the lifecycle only gives that explicit route to state 0. State 6 has its release tokens, while generic incomplete work uses `STOPPED` with an owned blocker (`pipeline/SKILL.md:33,42,50,55,75`; handoff contracts:73). This needs a mapping, not a new state.
3. `Only the approval role performs external actions` at skill:178 contradicts the new human-performed default. Read it as intended agent ownership, but correct the sentence to make approval the sole **agent** publisher and the owner of publication preparation/reconciliation for either performer.
4. An empty PR listing or absent comment is not automatically proof that an earlier request failed. It might still complete, visibility may be delayed, the query may be incomplete, or the object may have moved to another lifecycle status. The current instruction to read the target is necessary but does not define when absence establishes failure.
5. `The human decides whether the effect exists` at skill:175 is unsafe wording for an evidence question. The human decides the recovery action and may supply independently checkable evidence. A decision alone cannot establish an external fact. The existing evidence rules still prohibit that promotion; the local sentence should explicitly respect them.

**RECOMMENDATION — minimum contract, still owned by the existing files:**

| Record element | Required meaning |
|---|---|
| Action/attempt reference | Stable reference within the existing append-only approval entry, sufficient to associate every later read and retry with the original intent; no new storage system |
| Intent | Exact candidate, repository, source/destination refs and immutable command/payload or its retained artifact plus digest; preserve it before either performer acts |
| ATTEMPT_RESULT | Immutable outcome known from the original attempt. Existing `PUBLICATION_RESULT` may keep its spelling if explicitly defined as this field |
| RECONCILIATION_RESULT / CURRENT_KNOWN_STATE | An appended, explicitly named conclusion for that same action, linked to the read/evidence and its provenance. Preserve the original attempt and all earlier reads |
| Intent comparison | Whether the read remote object matches the authorized candidate, target and content; record a mismatch or unavailable comparison, not merely that a read happened |
| Partial components | For a genuinely compound external mutation, identify which named effects succeeded, failed or remain unknown |

The current conclusion is the latest supported observation for the same action and intent, as of that observation; a newer unsupported statement does not replace it. It is not a permanent assertion about future remote state. Recheck freshness before any dependent action.

State behavior should be explicit: a matching, established success is reused; an established terminal failure with no successful/unknown remainder may be retried only within still-current authorization; UNKNOWN stops advancement and retry; PARTIAL resumes only individually reconciled, unfinished components. Use the existing `STOPPED` result with a human-owned blocker to express NEEDS_HUMAN during release. Keep eligibility, publication outcome and gate PASS/BLOCKED/HELD separate.

For PRs, compare exact repository/source/destination, source head, title/body and other authorized mutable fields; search the lifecycle states needed to avoid recreating an existing object. For comments or transitions, read an attributable object/history or receipt, not just similar text. If the interface cannot establish that an earlier request is terminal and had no effect, retain UNKNOWN. Reconciliation is not an exactly-once guarantee against a concurrent writer; use existing host idempotency/conditional operations if actually available, otherwise stop ambiguous cases. No new idempotency service is proposed.

**Interruption:** the write-ahead intent and append-only entries are a sound durable design. An interruption after remote success but before result persistence leaves an unresolved intent to reconcile. An interruption before a human acts may also leave an intent with no result; do not reinterpret that as known failure. The contract must require recovery of all unresolved intents before new publication attempts. Actual persistence, hook completion and process recovery remain host-validation questions.

# 4. Publication-result contract

**FACT FROM FILE:** all four publication documents use the same four spellings. No file explicitly licenses retry on UNKNOWN. However, `PARTIAL names which part took effect` is the entire substantive definition (`handoff-contracts.md:251`), and there is no partial-outcome routing rule. Spelling consistency is not yet a usable status contract.

**RECOMMENDATION:** classify the mutation's specified effects, not the success of logging or fetching metadata.

| Status | Precise interpretation | Permitted next behavior |
|---|---|---|
| SUCCEEDED | Reliable result/read establishes all effects of the exact authorized action | Preserve evidence; perform any still-required exact-intent/freshness checks before dependent work; do not repeat the mutation |
| FAILED | Reliable evidence establishes terminal non-success with no successful or unknown effect | Report failure; a retry requires reconciled state and still-applicable authorization |
| UNKNOWN | The effect cannot be established, including lost responses or uncertain partial effects | Stop advancement/retry and reconcile; unresolved means human-owned blocker |
| PARTIAL | A predeclared compound mutation has at least one established successful effect and at least one unfinished effect; list each outcome, including UNKNOWN where applicable | Never retry the whole operation; reconcile unknown components and authorize/perform only the remaining exact work |

Push, create-PR and tracker-write are separate records under the existing contract. A successful push plus failed PR creation is not a PARTIAL push; it is two action outcomes. A read or logging failure is not a partial external mutation.

| Case | Attempt history | Reconciled/current conclusion and consequence |
|---|---|---|
| PR was created; trusted creation receipt establishes identity/effect; later URL/read confirmation fails | SUCCEEDED for creation | Creation is established as of that receipt. Required remote-content confirmation remains incomplete, so hold dependent work. Missing URL alone does not make creation PARTIAL |
| Create request may have succeeded but response was lost and the subsequent read fails | UNKNOWN | UNKNOWN; do not create a replacement PR |
| Lost create response; later read establishes the exact matching PR | UNKNOWN remains in history | Append SUCCEEDED with object identity and comparison evidence; reuse that object |
| PR exists, but source head, destination or body differs from authorized intent | Preserve the actual attempt result | Do not mark the exact authorized action successfully confirmed. Record mismatch and stop for a decision; no automatic repair or duplicate creation |
| Push response lost; a fresh read proves the exact named ref equals the authorized full commit | UNKNOWN remains in history | Append SUCCEEDED for the desired remote state. This proves the postcondition, not necessarily which actor caused it |
| Candidate commit is merely an ancestor of the remote branch tip | Whatever the attempt established | Insufficient for an instruction to push that exact candidate as the branch tip; do not silently accept extra commits |
| One declared external mutation changes some components but another fails | PARTIAL if established at return; otherwise UNKNOWN | Append per-component evidence; only unfinished, settled components can be considered for retry |
| Human says an action succeeded, without usable remote confirmation | Human report retained with provenance | UNKNOWN/unconfirmed for pipeline continuation; an assertion is not a successful remote verification |

The original attempt result and the reconciled state answer different questions. Both should survive; neither can be used as the gate verdict or as proof of current authorization. This addresses C1 without adding publication states to the delivery lifecycle.

# 5. Human publication default

**FACT FROM FILE:** the policy is sound in direction. `approvals.md:25,31-33` binds permission to the exact action/candidate/target and defaults push/PR creation to the human's credential. Approval release step 9 prepares the exact content, rechecks candidate/packet and explicitly requires a remote read. The optional agent route requires host permission, exact human authorization and honest credential/provenance recording. The default is not a claim that agent publication capability has already been withheld.

| Review question | Existing protection | Remaining C1 clarification |
|---|---|---|
| Which commit did the human push? | Exact candidate prepared; remote ref read required | Persist the full expected SHA and require equality with the observed ref, not a human assurance or ancestry match |
| Which branch/destination? | Exact repository/destination supplied to the human | Persist and compare both repository identities and full refs; local branch names alone are insufficient |
| Does PR content match? | Exact PR content prepared; unknown-effect recovery compares target/body | Require the same exact comparison on the normal human-success path; retain approved title/body/payload so an interrupted session can still compare |
| What remote re-read verifies it? | Named ref or PR read in approval:53-54 | A concrete record of observed ref SHA or PR identity/source head/destination/content, with evidence and provenance; an id/URL alone is not content verification |
| What if the human changes something? | Candidate changes invalidate evidence/review/permission (skill:110); material action changes need a decision (approvals:17) | New commit/source/proof basis returns through affected freeze/verification/review. A changed PR body or target needs exact-action authorization and impact assessment; do not automatically rerun unrelated tests for a text-only change |
| Can “I pushed it” advance the run? | No: approval:53 explicitly requires reading the remote | Make the compare-and-stop condition explicit so a successful read of the wrong object cannot be mistaken for confirmation |

**INFERENCE:** the missing durable intent payload is the main new human-path exposure. `handoff-contracts.md:239-248` requires action, candidate, target and an answer/reference, but not retention of the approved command/body itself; the primary conversation reference is optional. After interruption, the record can identify a PR without retaining the exact content it was authorized to have. Add that content reference to the existing publication record, not a new artifact family.

Authentication and action verification remain separate. A human's own SCM credential authenticates the actor to that platform, assuming the credential ownership assertion is true. A commit author string, PR existence or `Performed by: human` does not independently prove that credential was used. Retain the provenance of actor attribution; use a platform audit event when supplied. Do not silently turn a human report into OBSERVED_HOST authentication.

Keep `approvals.md` as policy owner. It already states the correct authorization distinctions; C1 should put schema detail in handoff contracts and the exact remote comparison in the approval role, with routing/retry meaning in the skill.

# 6. Provenance model

**FACT FROM FILE:** the intended HUMAN_RECORDED distinction is consistently preserved in `approvals.md:11-19`, `discovery-cost.md:13-22`, `handoff-contracts.md:248,253` and `harness-map.md:14,41`. None says an agent-written human name authenticates authorization. Independently authenticated events retain their own identity evidence rather than gaining trust from this label.

| Label | Assessment |
|---|---|
| HUMAN_RECORDED | Correct for a human-supplied decision with a recorded, independently unauthenticated representation. It describes the asserted source, not proof of authorship |
| AGENT_REPORTED | Correctly includes agent transcription of tool output; parsing or deterministic computation does not authenticate the input |
| OBSERVED_HOST | Correct for independently retained host/session events, but incorrectly includes “a human with a clock” at discovery-cost:13 and 42 |
| OBSERVED_TOOL | Correctly field-specific, with capture inspection required; a tool result retyped by the agent is not automatically observed evidence |
| INFERRED | Correctly used for named-human judgments, including finding-quality assessment; it must not substitute for a missing measurement |
| UNAVAILABLE | Correct: missing remains missing, not zero or an estimate; genuine observed zeros survive |

**C3 — false total ordering.** `discovery-cost.md:9` requires exactly one label, while line 22 requires the weakest provenance among inputs. The vocabulary has no defined total order and cannot honestly support one. An observed remote SHA and a human-recorded policy decision are different sources for different claims. Neither source becomes the other by selecting a “weaker” label. A host-recorded event is also not automatically authenticated for every field: a trusted host can record an unverified assertion.

**RECOMMENDATION:** preserve the input provenance set/lineage for mixed derivations and state what each source supports. Keep the conservative rule that agent-only inputs are never upgraded by parsing. For example, a publication-permission conclusion can cite an OBSERVED_TOOL remote comparison and a HUMAN_RECORDED decision, without treating the latter as an observed tool fact. No new collector, universal ranking, storage framework or additional runtime gate is needed. If a downstream display needs one summary label, it must not discard the source-specific limitations.

Also remove the human-clock example from OBSERVED_HOST unless an actual independent host capture supports that particular measurement. Retain the human measurement and its real source rather than relabelling it as host telemetry. Align the publication metric at discovery-cost:43 with C1: count UNKNOWN original attempts separately from currently unresolved actions; later successful reconciliation must not disappear from measurement.

These are measurement-correctness concerns, not evidence of an authenticated-authorization bypass. `discovery-cost.md:5,51,81` explicitly gates nothing.

**Finding-quality schema:** already multi-label. Line 64 explicitly permits TRUE_POSITIVE plus CHANGED_CODE, so replacing the taxonomy with a single enum would be a regression. TRUE_POSITIVE/FALSE_POSITIVE should be mutually exclusive for one resolved claim; split a mixed finding or preserve a revised adjudication. DUPLICATE and ALREADY_CAUGHT_BY_* are overlap dimensions; CHANGED_PLAN and CHANGED_CODE are effects; HUMAN_ONLY_DECISION is a resolution dimension and may coexist with a real policy gap. A brief adjudication convention before collecting metrics is enough. The current text does not use these labels for release or to skip a role; three runs are a signal for further measurement, not statistical proof or automatic policy change.

- **Agent-authored evidence remains weaker than independent capture.** A consistent digest or transcript can preserve an assertion without establishing its truth. Determine what the host actually captures before promoting provenance.
