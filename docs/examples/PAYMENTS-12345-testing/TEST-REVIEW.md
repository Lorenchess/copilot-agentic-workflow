## Findings

**F1** (round 1, HIGH, category: doubles/T4 prohibition 4 — **resolved by this correction round**). Round 1's `recordsRetryAttemptInAuditLog` doubled `AuditLogRepository` with a `@MockBean` recorder and verified only that `.save(...)` was invoked with the right argument shape, as its **last** assertion — the test's first assertion was its HTTP status check, which is what actually failed at the anchor in round 1 (the recorder-based `verify(...)` line was never reached pre-implementation either way). Persistence is the required outcome for AC4 (T3: "Persisted outcome... The real repository/mapping code against the storage the repository's tests already use... A fake repository: it proves the intent to save, not the mapping, transaction, or stored column"); doubling it is prohibited by T4 prohibition 4. Concretely, an incorrect implementation that calls `auditLogRepositoryRecorder.save(row)` on the mocked bean — never touching the real, Spring-wired `AuditLogRepository` or the embedded PostgreSQL at all — would have made this test pass while `AC4`'s persisted outcome remained entirely unproven, exactly the "call made, no row persisted" incorrect behavior derived above. **Round-2 correction**: two changes, both required. (1) The corrected test (`:14-38`) injects and asserts through the real `AuditLogRepository`, persisting into and reading back from the embedded PostgreSQL. (2) The assertions are reordered so the persisted row's presence is checked **first**, then its fields, with the HTTP status check moved **last** — the clause's own required outcome is now what the test's first assertion targets. As a direct, plainly-stated consequence: **round 1 failed at its status assertion; round 2 fails at the row-presence assertion instead** (`Expecting Optional to contain a value but it was empty` — see RED-REPORT.md). The incorrect behavior derived above now legitimately fails this test (no row would be found by `findByEntityTypeAndEntityId`, and that failure is now the very first thing the test checks). Resolved; no further action.
